# Шахматные дебюты — заметки для Claude Code

Игровое приложение для изучения шахматных дебютов (PWA). Сайт: https://nelegali.github.io/chess/
Пользуются двое: **Олег** (профиль p1) и **Сабина** (профиль p2), оба новички. Занимаются на iPhone
(часто приложение установлено на экран «Домой») и на ноутбуке (Mac). Весь интерфейс, тексты, комментарии
в коде и сообщения коммитов — **на русском**. С пользователем общаться по-русски, коротко и по делу.

## Как устроено

Статический сайт без сборки: ES-модули в `public/`, библиотеки лежат в `public/vendor/`.

```
public/index.html        оболочка
public/js/app.js         все экраны и маршруты (#/, #/o/:id, #/learn/:line, #/drill/:line, #/review, #/quiz,
                         #/free — свободная игра, #/theory, #/profile, #/link/:token/:profile — подключение устройства)
public/js/openings.js    база дебютов: OPENINGS, варианты (lines → steps {m, t, a}), lineSide(), findLine()
public/js/alternatives.js разобранные «а что если» для уроков
public/js/coach.js       тренер: оценка любого хода (explain → verdict + текст + demo), идея хода (moveIdea),
                         ходы из базы (bookMoves), forOpponentMove() — текст про ход соперника обращён к ученику
public/js/board.js       доска chessground + chess.js, стрелки, значки оценки (glyphShape), guardRedraw
public/js/store.js       прогресс (Лейтнер, XP, серия, достижения, журнал log), профили, синхронизация
                         (приватный гист GitHub или свой сервер), suggestNext() — что учить дальше
public/js/engine.js      Stockfish 17.1 lite (WASM, ~7 МБ, грузится лениво в Web Worker), MultiPV
public/js/popularity.js  % популярности: Lichess explorer (нужен токен) → иначе data/popularity.json
public/js/theory.js      теория, словарь терминов, разборы дебютов
public/js/version.js     версия и дата
public/sw.js             офлайн-кэш (stale-while-revalidate, перепроверка с cache: 'no-cache')
server.js                необязательный свой сервер: статика, /api/progress, /api/explorer
tools/build-popularity.mjs  сборка data/popularity.json из набора партий Kaggle (CC0)
tests/                   npm test: база дебютов, popularity.json, версии; логика прогресса
tests/e2e/               браузерные сценарии (Playwright), см. ниже
```

Вёрстка: телефон — `@media (max-width: 760px)`; цвета — CSS-переменные, тёмная тема по умолчанию,
светлая через `prefers-color-scheme: light`. Широкая раскладка свободной игры — от 1200px.

## Команды

```bash
npm test                      # быстрые проверки (их же запускает CI)
npm start                     # свой сервер на :8080 (PORT=8099 npm start — другой порт)
npm install && npx playwright install chromium   # один раз, для браузерных проверок
npm run e2e                   # все браузерные сценарии (сам поднимает server.js на :8099)
npm run e2e -- free pick      # выбранные сценарии
BASE_URL=https://nelegali.github.io/chess/ npm run e2e -- nested   # проверить опубликованный сайт
```

Скриншоты сценариев — в `tests/e2e/out/` (не коммитятся). Сценарий `walk` проходит все 26 вариантов
(~1–2 мин), `nested` и `quiz` тоже небыстрые.

## Выпуск версии — каждый раз

1. Поднять версию в **трёх** местах: `public/js/version.js` (`APP_VERSION` и `APP_DATE`),
   `public/version.json`, `VERSION` в `public/sw.js`. `npm test` проверяет, что номера совпадают.
   Новые файлы приложения добавлять в `SHELL` в `sw.js` (Stockfish туда не кладём — он большой).
2. `npm test` и затронутые сценарии `npm run e2e -- …`; для заметных изменений интерфейса — смотреть
   скриншоты на телефоне (iPhone 13) и ноутбуке, в светлой и тёмной теме.
3. Коммит, `git push`. Сайт публикует GitHub Actions (workflow **Pages**) из ветки по умолчанию —
   сейчас это `claude/relaxed-feynman-uzyf4m`. Дождаться, что **Test** и **Pages** зелёные
   (`https://api.github.com/repos/nelegali/chess/actions/runs?head_sha=<sha>`), и только потом
   говорить пользователю, что обновление на сайте. Установленное приложение подхватит новую версию
   само (плашка «Доступна новая версия»).

## Безопасность

- **Никогда** не коммитить и не вписывать в код токены (Lichess, GitHub). Они живут только в
  localStorage пользователя (`store.settings.lichessToken`, `githubToken`).
- Ссылка подключения устройства `#/link/<токен>/<профиль>` содержит токен GitHub (право только `gist`) —
  в интерфейсе везде предупреждение не пересылать её посторонним.

## Подводные камни, на которые уже наступали

- `.gitignore` содержит `/data/` (с косой чертой!) — данные своего сервера; без косой черты из
  репозитория пропадал `public/data/popularity.json`, и CI падал.
- chessground: при скрытой доске кэширует нулевые размеры → стрелки с NaN. Лечит `guardRedraw` в
  `board.js` (проверка реального размера + ResizeObserver). Сценарий `hideshow` это ловит.
- Нельзя класть кнопку внутрь кнопки (термины словаря — тоже кнопки): в карточках-кнопках
  использовать `richInButton`. Сценарий `nested`.
- Высоту ленты страниц свободной игры (`fitPagerHeight`) задаём только когда она реально листается
  (телефон), иначе на ноутбуке всё «едет».
- Свободная игра: касание хода соперника на телефоне сначала показывает позицию (`pickedUci`), второе
  касание — ход; клик мышью ходит сразу. Playwright `click()` — это мышь.
- Оценка тренера сверяется с движком (`judged()` в свободной игре): ход, который Stockfish считает
  лучшим, не называем ошибкой; ход без спасения — `lost`, а не `blunder`; ошибка соперника для
  ученика — «🎯 твой шанс» (зелёным).
- В тестах прогресс читается при загрузке модуля: после записи в localStorage делать `page.reload()`
  (смена только `#хэша` страницу не перезагружает).
- iPhone: у приложения с экрана «Домой» своя память, отдельная от Safari. Поэтому ссылку подключения
  можно вставить прямо в поле токена в Профиле.

## Данные прогресса (store.js)

`progress = { xp, days{дата: XP}, cards{lineId: {box, due, reps, lapses, last, best}}, learned{lineId: время},
achievements{id: время}, quizBest, log[{t, k: learn|drill|quiz|ach, id, …}] }` — отдельно на профиль
(`chess-openings-progress-v1` для p1, `…:p2` для p2). `merge()` объединяет копии с разных устройств
(по карточке — более свежая, журнал — без повторов). Профили и настройки — отдельные ключи.

## Как работать с пользователем

- Пользователь присылает скриншоты с телефона и ноутбука и коротко пишет, что не так. Сначала
  воспроизвести (Playwright, нужное устройство), потом чинить, потом показать результат.
- После каждой правки — выпуск версии (см. выше) и короткий отчёт по-русски: что изменилось и где это
  увидеть. Pull request не создавать, если не попросят.
